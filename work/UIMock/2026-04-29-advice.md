「完全リアルタイム」は**RTF ≤ 1（理想は0.5以下）を常時維持しつつ、数秒以内に部分結果を返す**設計が必要です。ポイントは“モデル選択”よりも**パイプライン（分割・VAD・逐次推論・状態管理）**です。PC／Android／iOSで現実的に成立する構成を分解して示します。

---

# ■ 共通アーキテクチャ（コア設計）

```
マイク入力（ストリーム）
   ↓（リングバッファ：2〜10秒）
VAD（発話検出・無音カット）
   ↓（3〜5秒チャンク化・オーバーラップ0.5〜1秒）
特徴量生成（Mel）
   ↓
ASR推論（軽量モデル・低beam）
   ↓
部分結果（partial）を即時表示
   ↓
確定処理（VADの無音検出でfinalize）
   ↓
後処理（句読点・誤変換補正）
```

### 設計上のキモ

* **チャンク長：3〜5秒**（長いと遅延、短いと精度低下）
* **オーバーラップ：0.5〜1秒**（語尾欠落防止）
* **VADは必須**（無音を捨ててRTFを稼ぐ）
* **partial / final の2段階出力**
* **状態保持（直前トークン）**で文脈を繋ぐ

---

# ■ PC（CPU/GPUあり）— 最も安定して“完全リアルタイム”達成

## 推奨構成

* 実装：faster-whisper
* モデル：small〜medium（GPUならlargeも可）
* 量子化：CPUならint8、GPUならfp16
* デコード：beam_size=1〜3（リアルタイム優先）

## 目安

* small + int8（CPU）：RTF **0.3〜0.8**
* medium + GPU：RTF **0.2〜0.6**

## 実装ポイント

* スレッド最大化（物理コア数）
* バッチは**ストリームでは小さめ（1〜2）**
* I/Oと推論を非同期化（キューで分離）

## 典型フロー（疑似）

```python
for chunk in stream():
    if vad.is_speech(chunk):
        text_partial = asr.transcribe(chunk, beam_size=1)
        emit_partial(text_partial)
    if vad.is_silence_tail():
        emit_final(aggregate())
```

# ■ Android（CPU中心・一部NNAPI）— “疑似リアルタイム”が現実解

## 推奨構成

* 実装：whisper.cpp or faster-whisper（NDK/Pythonラッパ）
* モデル：**small（必須）**
* 量子化：**int8**
* VAD：軽量（例：Silero）

## 目安（ハイエンドSoC）

* small + int8：RTF **0.8〜1.5**
  → **工夫すれば“体感リアルタイム”**

## 実装ポイント

* チャンクを**短め（3秒）**
* **beam_size=1**に落とす
* スレッド＝bigコア数に合わせる
* **前処理（ノイズ除去・VAD）で負荷削減**
* UIはpartialを優先表示

## アーキテクチャ

```
AudioRecord → RingBuffer
   → VAD（JNI）
   → 3秒Chunk
   → whisper.cpp（int8, beam=1）
   → partial表示（TextView）
   → 無音検出でfinal確定
```

## 注意

* mediumは不可（RTF>2で破綻）
* 発熱・サーマルスロットリングでRTF悪化 → **負荷平準化が必要**

# ■ iOS（CPU高性能・Metal活用可）— Androidより有利

## 推奨構成

* 実装：whisper.cpp（Metal有効） or Core ML変換
* モデル：**small（標準）／medium（条件付き）**
* 量子化：int8 or fp16（Metal時）

## 目安（A16/A17）

* small：RTF **0.5〜1.0**
* medium（int8/Metal）：RTF **0.8〜1.5**

## 実装ポイント

* AVAudioEngineで低レイテンシ入力
* Metal有効化で推論加速
* Android同様に**3〜5秒チャンク＋VAD**
* partialを即時反映（UXで遅延を隠す）

---

# ■ 重要パラメータ（全環境共通のチューニング）

| パラメータ       | 推奨     | 理由         |
| ----------- | ------ | ---------- |
| beam_size   | 1〜3    | 速度優先       |
| temperature | 0      | 出力安定       |
| chunk長      | 3〜5秒   | 遅延と精度のバランス |
| overlap     | 0.5〜1秒 | 語尾欠落防止     |
| threads     | 物理コア   | スループット最大化  |

---

# ■ “完全リアルタイム”を成立させる設計ルール

1. **smallモデル前提（モバイル）**
2. **VADで無音を切る（必須）**
3. **短チャンク＋オーバーラップ**
4. **partialを即出し（UXで体感改善）**
5. **beamを絞る（1〜3）**
6. **非同期パイプライン（録音/推論/UI分離）**

---

# ■ よくある失敗

* mediumを使う → RTF破綻
* チャンクが長い（>10秒） → 遅延増大
* VADなし → 無音で無駄計算
* beam=5以上 → 速度低下
* 同期処理 → UIフリーズ

---

# ■ 最短で動かす構成（モバイル共通）

* モデル：**small.int8**
* VAD：あり
* chunk：**3秒**
* overlap：**0.5秒**
* beam：**1**
* partial表示：ON

→ **“ほぼリアルタイム”で安定動作**
