
## 1. 推奨アプリ構成：マルチデバイス対応

PCでもモバイルでも「共通して」オフライン動作する、2026年現在の最強セットアップです。

| デバイス | 推奨アプリケーション | 役割 |
| :--- | :--- | :--- |
| **PC (Windows/Mac)** | **LM Studio** または **Jan** | モデルの管理と実行。オフライン対応が完璧。 |
| **iPhone / iPad** | **Locally AI** (LM Studio Mobile) | PCで使っているモデルをそのまま転送・実行可能。 |
| **Android** | **PocketLLM** | 軽量モデルの扱いに長け、完全オフラインで動作。 |

### 共通で使うべきAIモデル
* **Gemma 4 E2B (2.3B)** : Googleがモバイル・低スペックPC向けに開発したモデル。日本語の指示理解力が非常に高く、メモリ4GB程度の環境でも動きます。

## 2. 議事録作成のオフライン・ワークフロー

通信がない場所でも、以下の3ステップで議事録を完成させます。

### ステップ①：音声認識（文字起こし）
「PCもモバイルも」という条件の場合、LLMとは別に**Whisper（軽量版）**を利用します。
* **PC:** LM Studio内のLocal Inference機能（または **Whisper.cpp** の `base` モデル）。
* **スマホ/iPad:** アプリに内蔵された **Faster-Whisper** を使用。
* **コツ:** 通信不良環境では、音声ファイルを一度に処理せず、5分単位などで区切って文字起こしすると、低メモリ端末でもクラッシュしにくくなります。

### ステップ②：文字修正・整形
文字起こし直後のデータは「あー」「えー」が多く、誤変換も含まれます。ここで **Gemma 4 E2B** の出番です。
* **プロンプト例:**
    > 「以下の文字起こしから、不要なフィラー（あの、その等）を削除し、読みやすい話し言葉に修正してください。」

### ステップ③：要約・議事録化
最後に、同じモデルで「構造化」を行います。
* **プロンプト例:**
    > 「この内容を【議題】【決定事項】【次回の宿題】の形式でまとめてください。」

## 3. なぜこの構成が「低スペック」で動くのか？

1.  **2Bモデルの活用**: 以前のPoCで使った 7B モデル（Qwen2.5-coder）に比べ、**Gemma 4 E2B** は計算量が約1/3です。これにより、GPUがない一般的な事務用PCやスマホでも、発熱を抑えながら高速に推論できます。
2.  **量子化 (GGUF形式)**: モデルをそのまま使うのではなく、`Q4_K_M` などの「4ビット量子化」されたファイルを使います。これにより、モデルサイズが約1.5GB〜2GB程度になり、メモリ消費を劇的に抑えられます。
3.  **オンデバイス特化**: 2026年のトレンドである「SLM (Small Language Models)」は、まさにあなたの要望（オフライン・低リソース）を解決するために進化しました。
