## Q
元の英語クエリを日本語に翻訳しました：

「精度の高い音声認識システムを構築する必要があります。ネットワーク通信が不安定な顧客の会議室、市場、スーパー、物流倉庫などの複雑な環境で、iPad、スマホ、タブレットなどの携帯電子機器を使って会議記録を収集します。GitHubのWhisperと小さなLLMモデル（例: Qwen3の1.7Bなど）でPOCを作ったところ、日本語音声の認識精度が非常に低いという問題があります。良い提案はありますか？」

## A (中国語の回答)

### 快速POC建议（推荐路线）
1. **起步**：先用 **Vosk small-ja** + **Kotoba-Whisper** 在你的真实噪声录音上测试CER（字符错误率）。
2. **高精度**：切换到 **Qwen3-ASR-0.6B/1.7B**（streaming模式）或 **ReazonSpeech-k2-v2**。
3. **iPad优化**：用 **WhisperKit** 加载日语模型，转Core ML。
4. **后处理**：ASR输出 → 你提到的小LLM（如Qwen 1.7B）做标点/纠错/摘要。
5. **噪声增强**：所有模型前加简单VAD + RNNoise预处理。

**POC迭代路线图**
1. **快速验证**：下载Vosk Japanese模型 + ReazonSpeech/Kotoba-Whisper，在你的真实噪声录音上对比原Whisper的CER。
2. **移动集成**：iOS用Core ML + Swift；Android用Vosk/Kotlin；跨平台考虑Flutter + Vosk或whisper.cpp。
3. **噪声测试**：在市场/仓库实际录制，测量不同模型在SNR低时的表现。
4. **后端增强**：ASR输出 → 小LLM纠错/总结 → 会议记录生成。
5. **资源考虑**：目标设备内存/电池——优先<1GB模型 + 量化。测试实时性（streaming vs batch）。

### 1. **日语专项最强推荐（优先尝试）**
标准Whisper在日语上的表现不如英语或部分高资源语言，尤其在噪声下。推荐以下替代或增强方案：
**行动建议**：先在你的POC数据（真实会议/仓库录音）上benchmark这些模型的CER/WER。重点测试噪声、多说话者、重叠、日语口语/方言场景。用Hugging Face或官方repo快速试跑。

- **Kotoba-Whisper**
  - GitHub: https://github.com/kotoba-tech/kotoba-whisper
  - 优势：基于Whisper蒸馏的日语专用模型（v2.0 / v2.2等），针对日语优化，精度高且模型较小。支持GGML格式，可直接用于whisper.cpp。
  - 部署：iOS推荐转Core ML；Android/跨平台用whisper.cpp或GGUF量化。
  - 适合：Apple设备（iPad/iPhone）上的高效日语转录。

- **Vosk small-ja**
 - 官方下载：https://alphacephei.com/vosk/models/vosk-model-small-ja-0.22.zip (48MB)。
 - GitHub 主 repo：https://github.com/alphacep/vosk-api （支持 iOS/Android 等移动部署）。


### 2. **移动设备部署优化（iPad/iPhone优先，Android次之）**
- **現状無視**


### 3. **应对复杂环境（噪声、多说话者）的工程技巧**
- **音频预处理**：用RNNoise、WebRTC VAD 或 Speex 做降噪；分段处理（避免长音频一次性喂模型）。
- **说话者分离（Diarization）**：WhisperX + NeMo MSDD，或集成简单聚类。会议室多说话者时非常有用。
- **后处理**：用小型LLM（Qwen 1.7B或类似）做纠错、标点、摘要。输入ASR原始输出 + 上下文提示（如“这是物流仓库会议，日语口语”），可显著提升可读性。
- **领域适配**：
  - 收集你客户的特定数据（会议/超市/仓库录音），用LoRA微调Whisper/Kotoba/Qwen3-ASR（日语部分）。少量数据就能大幅降低CER。
  - 添加自定义词汇表（物流术语、公司名等）。

- **混合模式**：弱网络时优先离线，信号好时可选云回退（但你强调无法保证网络，所以以离线为主）。
